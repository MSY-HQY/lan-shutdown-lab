# 两台电脑实操与排错

## 准备

- 两台电脑，连**同一个 WiFi 或同一个交换机**（同一个网段，IP 前三段相同）
- 两台都装了 Python 3.8+
- 只在你自己拥有、或对方明确同意你测试的机器上做

## 步骤

### 1. 操作端先起

```
python operator.py
```

输出里会列出本机局域网 IP：

```
本机局域网 IP（被控端里填的就是其中之一）：
    192.168.1.10
监听端口 4444，等待被控端连进来……
```

记下 `192.168.1.10` 这类地址（有多个就挑跟另一台同网段的那个）。

### 2. 被控端起

在另一台上：

```
python target.py 192.168.1.10
```

或者直接 `python target.py`，它会问你一次，答案记进 `被控端配置.txt`，下次不用再输。

顺序其实无所谓——被控端连不上会每 3 秒重试一次。

### 3. 防火墙

操作端第一次运行时 Windows 会弹窗：

> Windows Defender 防火墙已阻止此应用的部分功能

勾上「专用网络」，点「允许访问」。

没弹窗、又连不上，就手动加：

控制面板 → Windows Defender 防火墙 → 高级设置 → 入站规则 → 新建规则 → 端口 → TCP → 特定本地端口 `4444` → 允许连接 → 全部勾上 → 起个名字。

### 4. 先验通路，再试关机

在操作端敲 `4`：

- 被控端那边响两声系统提示音
- 工程版还会回一行「测试命令已执行（响了两声），没有动电源」

听到／看到反应，说明链路通了。

然后敲 `1`：被控端 30 秒后关机，倒计时里敲 `3` 可取消。

> 30 秒是留给你反悔的。真要确认，就在对方机器上把没保存的东西先存掉。

## 排错表

| 症状 | 检查顺序 |
| --- | --- |
| 被控端一直「连不上 … 3 秒后重试」 | ① IP 是不是操作端那台的？② 两台网段是否一致（各自 `ipconfig`）③ `ping 对方IP` 通不通 ④ 操作端防火墙放行 4444 没有 |
| 能连上，但敲命令没反应 | 被控端窗口有没有打印「收到命令」；没有 → 可能连到了旧进程，把两端都关掉重开 |
| 敲 `4` 没声音 | 命令执行了，只是系统关了提示音：设置 → 系统 → 声音 → 更多声音设置 → 把「默认提示音」打开 |
| 关机没生效 | 用管理员身份运行被控端；杀软可能拦 `shutdown` 相关操作 |
| 端口被占用 | 工程版可用 `set LAB_PORT=4455` 换端口（两端要一致）；精简版改两个文件里的 `端口 = 4444` |
| 打包成 exe 后在家里那台被删／报毒 | 别打包，直接装 Python 跑 `.py` 最稳 |
| exe 双击后黑窗停住几秒 | `--onefile` 在解包，不是卡死 |

## 打包（可选）

```
pyinstaller target.py --onefile --console
```

`--onefile` 的产物启动时会解包到临时目录，所以**配置文件的路径要特殊处理**——`__file__` 那时指向临时目录。`src/minimal/target.py` 里已经写了判断：

```python
if getattr(sys, "frozen", False):
    基准目录 = os.path.dirname(sys.executable)   # 打包后：exe 所在目录
else:
    基准目录 = os.path.dirname(os.path.abspath(__file__))
```

写死 IP 的版本（`target_hardcoded_ip.py`）更省事：把 `IP = "192.168.1.10"` 改好直接打包，拷过去双击就行。

## 提醒

- 家用路由器的 IP 是动态分配的，隔几天可能变。变了就重新填。
- 别把这个用在学校机房、公司、宿舍的公共电脑上。不是技术问题，是合规问题。
