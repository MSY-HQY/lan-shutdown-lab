# 为什么以前"只关到自己电脑"

很多人照着短视频敲完这两段代码，一试，关的是自己的电脑。代码本身没写错，问题出在**谁连谁**。

## 先看清楚方向

```
被控端(target.py)  ──主动连接──►  操作端(operator.py)
                                    bind 0.0.0.0:4444
                                    listen / accept
       ◄──────发一个字符 "1"──────
 收到 "1" → 关机
```

被控端里那行 `s.connect((IP, 4444))` 的意思是"**连回操作端那台电脑**"。所以 `IP` 要填的永远是**操作端那台电脑**的局域网地址。

如果填了一个本机地址，被控端就变成了"自己连自己"，操作端发过来的 `1` 绕一圈回到自己身上，关掉的自然是自己这台机器。

## 常见的三种填错

| 填的值 | 为什么不对 |
| --- | --- |
| `127.0.0.1` | 回环地址，指向自己 |
| `169.254.x.x` | 链路本地地址。VMware / VirtualBox 的虚拟网卡拿不到 DHCP 时会自动变成这个网段，看着像"我的 IP"，其实只在虚拟网卡内部有效 |
| 本机在另一个网段的地址 | 比如手机热点下是 `192.168.43.x`，接了路由器又是 `192.168.1.x`，填错网段照样连到自己或干脆连不上 |

正确的值长这样：`192.168.1.10`、`192.168.31.20`、`10.0.0.5` —— 就是**操作端那台电脑** `ipconfig` 里那个"IPv4 地址"。

## 怎么一眼判断

被控端启动时会打印：

```
被控端 已启动
本机 IP  ： 192.168.1.23
操作端   ： 192.168.1.10
```

- 「操作端」那行是不是**另一台电脑**的地址？是 → 方向对了
- 两台前三位（`192.168.1.`）一样吗？不一样 → 不在一个局域网，先解决网络
- 出现 `127.0.0.1`、`169.254.` → 填错了

## 顺带解释另一个误区

`bind(("0.0.0.0", 4444))` 里的 `0.0.0.0` 不是"任意 IP 都能连进来"的意思，而是"**本机所有网卡都监听**"。所以如果本机某块虚拟网卡上正好有 `169.254.x.x`，而被打包好的被控端又写了这个地址，它就会连回那块虚拟网卡——也就是这台机自己。这几乎是"只关到自己"最常见的成因。
