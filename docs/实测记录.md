# 实测记录

这份文件记录的是两次真实跑通的验证，不是设想。

## 一、同一台机器自测（127.0.0.1）

两端在同一台 Windows 上对跑，被控端连 `127.0.0.1`：

| 命令 | 结果 |
| --- | --- |
| `4` | 被控端响系统提示音，回「测试命令已执行（响了两声），没有动电源」 |
| `5` | 回「主机名 蓝水；本机 IP 192.168.1.245」 |
| `3` | 回「当前没有待执行的关机或重启」（系统返回 1116） |
| `9` / `q` | 两端正常退出，退出码均为 0 |

## 二、经真实网卡连接

被控端连本机的局域网地址（`192.168.1.245`，不是回环），对面拿到的来源地址就是 `192.168.1.245`，
命令收发与上面一致——说明走的是真实网络栈，不是回环特例。

## 三、被控端被强杀时的行为

操作端窗口直接关掉（模拟对面失联），被控端先打印「连接断了……重连中」，
随后每 3 秒重试一次（`10061 由于目标计算机积极拒绝，无法连接`），进程不退出、不崩。

这一条在原版代码里是崩的：`recv()` 会抛 `ConnectionResetError`（10054），没有 try/except 就是整个程序退出。

## 四、打包成 exe

`pyinstaller target.py --onefile --console` 打出来的 7.9 MB 单文件，
启动需要几秒解包（黑窗口停住不是卡死），连接与命令执行均正常。
Windows Defender 在本机未拦截，但从别人机器上被拦是常态。

## 五、没验证过的

跨两台真机、跨路由器的场景还没有实测记录。文档里「两台电脑怎么试」那一节是按协议推理写的，
第一次在真实两台机器上跑通之后，把结果补到这里。
